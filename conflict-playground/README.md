**[04. ハンズオン本編](../docs/04_branch_pr.md) を1周してから来てください。**

使い方の手順はこちら → **[05. 番外編1：コンフリクト解消](../docs/05_extra_conflict_revert.md)**

## ここは何をしてもOKです

- ファイルを壊しても大丈夫です
- 変な内容をcommitしても大丈夫です
- コンフリクトを起こしても大丈夫です（**むしろそれが目的です**）

**本編（`members/`）には一切影響しません。** 安心して失敗してください。

---

## なぜ「わざと」衝突させるのか

本編では、全員が `members/<自分のID>.md` という**別々の新規ファイル**を作りました。
同じ行を触る人がいないので、**構造的にコンフリクトが起きません。**

これは意図的な設計です。初回で全員コンフリクトしたら、30分では終わりません。

でも、**実務では必ずコンフリクトに出会います。**

そして、初めて `CONFLICT` の文字を見た人は、たいてい以下のどれかをやります：

- ❌ フォルダごと消してcloneし直す
- ❌ ターミナルを閉じて見なかったことにする
- ❌ 記号（`<<<<<<<`）が残ったままcommitしてしまう

**安全な場所で1回経験しておけば、本番で慌てません。**

そして最初に知っておいてほしいこと：

> **コンフリクトが起きても、あなたのコミットも相手のコミットも1つも失われていません。**
> Gitは「どっちを採用すべきか、意味を判断できるのは人間だけだから決めて」と聞いてきているだけです。
>
> どうにもならなくなったら、いつでもこれで元に戻せます：
> ```bash
> git merge --abort
> ```

## 参加手順（ざっくり）

詳細は [05. 番外編1](../docs/05_extra_conflict_revert.md) にあります。

1. `main` を最新にする（`git pull`）
2. 練習用ブランチを切る（`practice/<自分のID>-conflict`）
3. `guestbook.md` の **「今日のひとこと」の行**を書き換えてcommit
4. `git pull origin main` → 💥 **CONFLICT が出る**
5. `<<<<<<<` `=======` `>>>>>>>` を探して、あるべき形にする
6. `git add` して `git commit`

**5番の「記号を全部消す」が最頻出ミスです。** 気をつけてください。
