# members/ — 自己紹介ページ置き場

**ここが、今日のハンズオンであなたが触る唯一のフォルダです。**

---

## やること

**`members/<あなたのGitHub ID>.md` というファイルを、新しく1つ作る。**

例：GitHub IDが `taro-yamada` なら → `members/taro-yamada.md`

たったこれだけです。

---

## 手順

詳しい手順はこちら：

| 進め方 | 資料 |
|---|---|
| **ターミナルで進める** | [docs/04_branch_pr.md](../docs/04_branch_pr.md) |

### ざっくり言うと

1. [`_TEMPLATE.md`](_TEMPLATE.md) をコピーする
2. ファイル名を **自分のGitHub ID** に変える
3. 中身を書き換える
4. commit → push → PR

---

## ルール

| # | ルール | 理由 |
|---|---|---|
| 1 | ファイル名は **`<自分のGitHub ID>.md`** | 誰のファイルか一目で分かるため |
| 2 | **他の人のファイルは編集しない** | 勝手に書き換えられたら困りますよね |
| 3 | **個人情報は書かない** | このリポジトリはPublic（誰でも見られる）です |
| 4 | 全部埋めなくてよい | 書きたいことだけでOKです |

### 書かないでほしいこと

- 本名（フルネーム）
- 住所・電話番号・メールアドレス
- 学籍番号
- 他人の情報

**ニックネームやGitHub IDだけで全く問題ありません。**

## なぜこの設計なのか（講師の意図）

**全員が「別々の新規ファイル」を作るので、コンフリクト（衝突）が構造的に起きません。**

同じファイルの同じ行を複数人が編集すると、Gitは「どっちを採用するか」を人間に聞いてきます。
初回でそれが起きると、30分では終わりません。

**わざとコンフリクトを起こす練習場**は別に用意してあります
→ [`conflict-playground/`](../conflict-playground/)（[番外編1](../docs/05_extra_conflict_revert.md)で使います）
